1. 소스 옮기기
============================================================
내부망에서 GitHub 접근이 안 되면 git bundle(또는 zip)로 옮깁니다. 개발 PC에서:

  git bundle create db-cockpit.bundle main

내부망 서버의 기존 저장소에서:

  git pull <번들 경로>/db-cockpit.bundle main

(기존 폴더가 git 저장소가 아니면 새 폴더에 git clone db-cockpit.bundle 후,
 0번에서 백업한 .env와 reports/를 새 폴더로 복사)

이 저장소는 node_modules, client/node_modules, instantclient_19_25, 빌드된 public/까지
전부 git에 커밋하는 방식이라 보통 npm install이나 프론트 빌드가 따로 필요 없습니다.

React 전환으로 서버에 추가로 설치할 것은 없습니다. 브라우저가 받는 것은 빌드된 public/
(html/js 정적 파일)뿐이고 Express가 예전처럼 그대로 서빙합니다. 내부망 서버에서 프론트
소스(client/src)를 직접 고쳐 다시 빌드할 때만 client/node_modules의 Vite가 필요한데,
이것도 커밋돼 있습니다 (단, Windows x64용 바이너리만 들어 있어 다른 OS에서 빌드하려면
client/에서 npm install 필요).

예외: oracledb 등 일부 패키지는 OS/CPU별 네이티브 바이너리를 씁니다. 개발 PC(Windows x64)와
내부망 서버의 OS/아키텍처가 다르면 서버에서 직접 npm install을 실행하고, Instant Client도
그 환경용으로 준비해야 합니다. Node.js 버전은 개발 PC(v24)와 맞추는 것을 권장합니다.

새 PC/서버에 처음 설치하는 경우 (인터넷이 되는 PC에서 받아서 옮김):
  - Node.js v24 LTS Windows Installer(.msi, x64) 설치. 설치 후 VS Code/터미널을 완전히 껐다 켜야 PATH가 잡힘.
  - Visual C++ 재배포 패키지(vc_redist.x64.exe) 설치 — 프로젝트에 들어 있는 Oracle Instant Client 19가
    필요로 함. 없으면 서버 기동 시 "DPI-1047: Cannot locate a 64-bit Oracle Client library" 에러.
  - VS Code 터미널에서 npm 실행 시 "스크립트를 실행할 수 없으므로 npm.ps1..." 에러가 나면
    Set-ExecutionPolicy -Scope CurrentUser RemoteSigned 를 1회 실행하거나 터미널을 Command Prompt로 바꿈.
  - .env의 APP_HOST는 그 PC/서버의 IP로 맞출 것 (예전 PC의 IP가 남아 있으면 EADDRNOTAVAIL 에러).

  node -e "
    const oracledb = require('oracledb');
    const fs = require('fs');
    require('dotenv').config();
    (async () => {
      oracledb.initOracleClient({ libDir: './instantclient_19_25' });
      const conn = await oracledb.getConnection({
        user: process.env.NODE_ORACLEDB_USER,
        password: process.env.NODE_ORACLEDB_PASSWORD,
        connectString: process.env.NODE_ORACLEDB_CONNECTIONSTRING,
      });
      const sql = fs.readFileSync('scripts/add_users.sql', 'utf-8');
      for (const stmt of sql.split(/;\s*\n/).map(s => s.trim()).filter(s => s && !s.startsWith('--'))) {
        await conn.execute(stmt, [], { autoCommit: true });
      }
      await conn.close();
    })();
  "

(파일명만 바꿔서 스크립트마다 한 번씩 실행)

4. 대상 DB 계정 권한 확인 (새 화면용)
============================================================
Databases 화면에 등록된 대상 DB 접속 계정에 아래 권한이 있어야 각 화면이 동작합니다.
SYSTEM 등 DBA 계정으로 등록돼 있다면 대부분 이미 있습니다.

  - Real-Time        : V$SESSION, V$PROCESS, V$SQL 조회.
                       SQL 경과시간 산점도/세션 상세의 ASH 요약은 V$ACTIVE_SESSION_HISTORY
                       (오래된 구간은 DBA_HIST_ACTIVE_SESS_HISTORY), 공유 풀에서 밀려난 SQL은
                       DBA_HIST_SQLTEXT / DBA_HIST_SQLSTAT / DBA_HIST_SNAPSHOT 조회.
                       ※ ASH/AWR은 Oracle Diagnostics Pack 라이선스가 필요한 기능입니다.
                         권한/라이선스가 없는 DB는 산점도만 "조회 불가"로 표시되고 나머지는 동작합니다.
  - Stats Job Status : DBA_SCHEDULER_JOBS, DBA_SCHEDULER_JOB_RUN_DETAILS 조회.
                       "지금 실행"은 다른 스키마 소유 잡을 실행하므로 CREATE ANY JOB 등
                       잡 실행 권한이 추가로 필요.
  - ILM Partition    : 해당 DB에 PGDBA.DEL_JOB_TABLE_LIST 테이블이 있어야 하고,
    Retention          그 테이블에 대한 SELECT / INSERT / UPDATE 권한.
  - Object Compare   : 비교하는 양쪽 DB 모두에서 아래 딕셔너리 뷰 조회 (읽기만 함).
                       DBA_USERS, DBA_TABLESPACES, DBA_DATA_FILES, DBA_TEMP_FILES,
                       DBA_TABLES, DBA_TAB_COLUMNS, DBA_INDEXES, DBA_IND_COLUMNS,
                       DBA_IND_EXPRESSIONS, DBA_VIEWS, DBA_MVIEWS, DBA_SEQUENCES,
                       DBA_SYNONYMS, DBA_SOURCE, DBA_OBJECTS
  - Parameter Compare: 비교하는 양쪽 DB 모두에서 V$SYSTEM_PARAMETER, V$INSTANCE 조회.
                       hidden(_) 파라미터까지 전부 비교하려면 각 DB에서 SYS로
                       scripts/grant_hidden_parameter_views.sql <접속계정> 을 1회 실행
                       (X$KSPPI/X$KSPPSV 래퍼 뷰 2개 생성 + SELECT 권한 부여, CDB면 해당 PDB에서).
                       값은 인스턴스 기준(V$SYSTEM_PARAMETER와 같음)으로 비교합니다.
                       안 해도 화면은 동작하며, 그때는 직접 설정한 hidden만 비교됩니다.

  - Data Pump        : (Maintenance > Data Pump, 대상 DB 쪽) 접속 계정에
                       DATAPUMP_EXP_FULL_DATABASE / DATAPUMP_IMP_FULL_DATABASE 롤 (DBA 롤에 포함),
                       쓸 DIRECTORY에 대한 READ/WRITE 권한(덤프/로그 생성 + 화면에서 로그 읽기 +
                       parfile을 DB 서버에 바로 저장), UTL_FILE 실행 권한(보통 PUBLIC에 있음 —
                       보안 설정으로 회수된 DB라면 GRANT EXECUTE ON UTL_FILE TO <접속계정>),
                       DBA_DIRECTORIES, DBA_SEGMENTS, DBA_LOBS, DBA_TABLES, DBA_DATAPUMP_JOBS,
                       V$SESSION_LONGOPS, V$DATABASE, V$VERSION 조회.
                       덤프/로그 파일은 DB 서버의 DIRECTORY 경로에 생깁니다 (앱이 도는 PC가 아님) —
                       디스크 여유 공간 확인. PARALLEL 2 이상은 Enterprise Edition에서만 됩니다
                       (Standard/Free는 화면에서 1로 고정).

    hidden 파라미터용 뷰 — sqlplus 대신 Orange 등 SQL 툴로 실행할 때:
    SYS를 SYSDBA 권한으로 접속한 뒤 아래를 "스크립트 실행"(전체 실행)으로 돌립니다.
    접속계정 자리에는 Databases 화면에 등록된 그 DB의 접속 계정(예: SYSTEM)을 넣습니다.

      -- CDB$ROOT로 접속했다면 앱이 접속하는 PDB로 먼저 이동 (아니면 생략)
      ALTER SESSION SET CONTAINER = PDB명;
      CREATE OR REPLACE VIEW sys.x_$ksppi  AS SELECT * FROM x$ksppi;
      CREATE OR REPLACE VIEW sys.x_$ksppsv AS SELECT * FROM x$ksppsv;
      GRANT SELECT ON sys.x_$ksppi  TO 접속계정;
      GRANT SELECT ON sys.x_$ksppsv TO 접속계정;

    확인: 접속계정으로 SELECT COUNT(*) FROM sys.x_$ksppi; 가 숫자로 나오면 성공.
    뷰는 조회할 때마다 X$를 실시간으로 읽으므로 파라미터를 바꿔도 다시 실행할 필요 없음
    (단 DB를 새로 만들거나 이관하면 그 DB에서 다시 실행).
    지우려면: DROP VIEW sys.x_$ksppi; DROP VIEW sys.x_$ksppsv;
